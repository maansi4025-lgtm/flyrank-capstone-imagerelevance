# Evidence — proof for every requirement

One pasted proof per requirement from Section 6 of the brief.

## AI processing

**Vision model produces structured output validated against a schema; invalid responses are never trusted.**

Real example of a rejected, invalid response (giraffe misclassification on `deer_5.jpg`):

```
category
  Input should be 'fox', 'wolf', 'dog', 'bear' or 'deer' [type=literal_error, input_value='Deer', input_type=str]
```

The record was never stored — it was marked `"status": "flagged"` in `output/image_tags.json`.

**Low-confidence classifications are flagged instead of accepted.**

`pipeline/batch_tag.py` marks any result with `confidence < 0.6` as flagged, regardless of schema validity (see `process_all_images()`).

**Images are processed through a batch background job with retries.**

Full batch run: `python pipeline/batch_tag.py` — processed 50 images, 49 tagged, 1 flagged (`deer_5.jpg`, after 2 attempts failed schema validation).

**Vision and embedding costs are tracked per call.**

`output/vision_cost_log.jsonl` — one line per call, e.g.:

```
{"image": "bear_1.jpg", "duration_ms": 8581.8, "timestamp": "2026-09-21T10:08:55.901973+00:00", "status": "tagged"}
```

## Matching system

**Image and post embeddings are stored; posts return ranked image suggestions.**

`output/image_embeddings.json` (49 records), `output/post_embeddings.json` (12 records). Example ranked suggestion via API:

```
GET /posts/post-1/suggestion
{"result":"accepted","image":"red-fox_10.jpg","similarity":0.6519, ...}
```

**Semantic matching works for equivalent concepts — "red fox" matches "Vulpes vulpes".**

`post-6`, titled "Vulpes vulpes: the scientific study of foxes" (the word "fox" never appears in the post text), correctly matched `red-fox_6.jpg` with similarity 0.5303.

## Safety layer

**The mismatch guard rejects incorrect recommendations — the wolf-on-a-fox-post scenario provably fails.**

```
=== FORCED CANDIDATE TEST ===
Post: "The behavior of red foxes" (expects: fox)
Forced candidate: wolf_1.jpg (actual category: wolf)
Similarity: 0.3894
Guard result: REJECTED
Reason: Animal category mismatch: expected fox, detected wolf
```

**Rejections include a human-readable explanation.**

See above — every rejection includes a specific `reason` string generated by `guard_check()` in `pipeline/matching.py`.

**When no image clears the bar, the system answers "no confident match" with reasons.**

```
post-12 (The lifecycle of the monarch butterfly): no_confident_match
Reason: "Similarity 0.11 below threshold 0.35"
```

## Backend

**Database models for images, tags, embeddings, posts, suggestions, approvals/rejections.**

Implemented as structured JSON files (`output/image_tags.json`, `output/image_embeddings.json`, `output/post_embeddings.json`, `output/reviews.json`) rather than a relational database — see `DESIGN.md`'s "Database design" section for the intended schema; at this corpus scale (49 images, 12 posts) flat files hold the same structure without needing Postgres running. This is stated explicitly as a known simplification in the README's limitations.

**API endpoints validated; the review workflow (approve / reject / inspect why) exists.**

```
GET /posts -> 200, lists all 12 posts
GET /posts/post-1/suggestion -> 200, full ranked suggestion + reasoning
POST /posts/post-1/review {"decision":"approved"} -> 200, recorded
GET /reviews -> 200, shows the recorded decision
```
